You won. You never collected.

DreamDEX Event Contracts settle on schedule and the settled market leaves the live list — so a winning position quietly stops appearing anywhere in the UI. Reclaim scans any wallet's on-chain outcome balances, finds settled markets still holding redeemable tokens, and shows exactly how each one resolved before you prepare a batch redemption.

How a market resolves permissionless

Oracle answer is posted
price sources report, the median is taken, the interval is chosen
Reactivity delivers it to the OracleHub
no keeper, no cron — the chain invokes the callback
Market flips to Resolved and finalizes
payout vector is written; redemption opens immediately
The market leaves the live list
loadMarkets() skips finalized binaries — this is where winnings go missing
Winner redeems 1 collateral per contract
settlement fee is 0 on dreamDEX, so winners get 1:1
Each market's settlement question is reachable through its OracleBind, so Reclaim deep-links every row to the oracle explorer and the resolution can be audited source by source.

SDK compatibility — markets-sdk
client.getClaimable(account) is indexer-backed and capped at 200 holdings in SDK 0.30.0
Write path — trader.redeemMany
batch-ready SDK candidates, with both voided legs preserved
The SDK's getClaimable rows are shaped as redeemMany input, but the bounded SDK result may be a subset for active wallets. Reclaim shows that limitation instead of calling it authoritative.
